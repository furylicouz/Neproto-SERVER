# NP/2 v2.1: Encrypted Mobile Data Plane

Status: approved for implementation

Date: 2026-07-17

## Outcome

NP/2 v2.1 adds two protocol-level capabilities:

1. Every post-authentication NP/2 cell is protected by directional AEAD independently of TLS or DTLS.
2. The iOS packet tunnel terminates TCP in a userspace IP stack and opens NP/2 streams directly. It does not start or connect to a SOCKS listener.

The desktop loopback SOCKS5 listener remains an optional application adapter. It is not part of the NP/2 public wire format.

## Security Boundary

```text
iOS application traffic
        |
      utun
        |
userspace IPv4/IPv6 + TCP stack
        |
  NP/2 encrypted streams
        |
WebRTC (DTLS/SCTP) or HTTPS (TLS/WebSocket)
        |
     NP/2 server
        |
 target TCP service
```

NP/2 cell encryption is end-to-end between an NP/2 client and the NP/2 server. The server must decrypt the target metadata and stream bytes to act as the exit proxy. Application protocols such as HTTPS provide their own independent browser-to-site encryption beyond the NP/2 server.

## Negotiation

`FeatureCellAEAD` is a mandatory negotiated NP/2 v2.1 feature. A v2.1 client does not send application cells if the server challenge does not advertise it. A v2.1 server does not start a multiplexer when the client response omits it. This creates a clean failure against a v2.0 peer instead of misinterpreting ciphertext as cells.

The existing challenge/response/confirm transcript remains the key agreement and peer-authentication mechanism. It already binds the root secret, server identity, carrier, both random nonces, and negotiated feature set.

## Directional Keys

HKDF-SHA-256 derives independent material from the authenticated transcript:

```text
c2s_key          = HKDF(auth_key, transcript_salt, "NP2 cell c2s key")
s2c_key          = HKDF(auth_key, transcript_salt, "NP2 cell s2c key")
c2s_nonce_prefix = HKDF(auth_key, transcript_salt, "NP2 cell c2s nonce")[:4]
s2c_nonce_prefix = HKDF(auth_key, transcript_salt, "NP2 cell s2c nonce")[:4]
```

Keys are never reused across authenticated sessions because each transcript contains fresh server and client CSPRNG nonces. Directional separation prevents reflection across client-to-server and server-to-client traffic.

## Encrypted Cell Record

The plaintext is the complete encoded NP/2 cell after adaptive padding has been applied. ChaCha20-Poly1305 seals it with an implicit ordered-record counter:

```text
nonce      = nonce_prefix[4] || uint64_be(record_counter)
aad        = "Neproto NP/2 cell" || protocol_version || carrier || direction
wire_record = ciphertext || poly1305_tag
```

The counter starts at zero independently in each direction and is never transmitted. Both supported carriers are ordered and reliable. A duplicated, deleted, reordered, modified, reflected, or injected record therefore causes authentication failure and closes the complete NP/2 session. Counter exhaustion also closes the session.

Handshake messages remain outside this record layer because they create its keys. They are authenticated by HMAC and are already carried inside TLS or DTLS.

No custom cipher or hash primitive is introduced.

## iOS TCP Data Plane

The Packet Tunnel obtains a duplicated utun file descriptor from NetworkExtension. A pinned userspace TCP/IP stack consumes IPv4 and IPv6 packets with the Darwin 4-byte address-family prefix.

For each accepted TCP flow:

1. Read the numeric destination IP and port from the TCP endpoint metadata.
2. Encode that destination using the existing canonical NP/2 `OPEN` target format.
3. Open one logical stream on the authenticated NP/2 multiplexer.
4. Relay bytes bidirectionally and preserve TCP half-close behavior.
5. Reset and release the stream on cancellation, protocol failure, or tunnel shutdown.

### Performance-safe flow control

The iOS production profile advertises a 2 MiB receive window. This is large
enough to keep a mobile path busy across the measured 100–180 ms RTT range but
remains bounded by the existing 16 MiB protocol maximum and the configured
stream/session limits.

Consumed credit is coalesced into `WINDOW_UPDATE` cells using a threshold of
one eighth of the stream window, clamped to the stream window and a maximum of
256 KiB. Credit is flushed earlier when the sender can be stalled and when the
final buffered bytes of a peer-closed stream are consumed. Aggregation changes
neither the additive credit semantics nor the wire encoding, so an optimized
client remains compatible with the deployed NP/2 v2.1 server.

The `web` cover profile, its padding buckets, dummy budget, 0–12 ms bounded
jitter, and mandatory cell AEAD remain enabled. Performance work must not turn
the profile into an unpadded bulk mode or append bytes outside the valid carrier.

The production adapter carries system DNS inside the encrypted NP/2 data plane.
It observes only validated query/response pairs in a bounded, TTL-limited
in-memory attribution cache so subsequent numeric TUN flows retain the domain
needed by authoritative Domain and GeoSite routing. DNS names are not persisted
or logged. Native NP/2 UDP uses bounded authenticated associations and retains a
reliable-stream fallback when carrier datagrams are unavailable.

## Lifecycle

Startup order:

1. Load the profile and root secret from the Keychain-backed reference.
2. Establish and authenticate an NP/2 carrier before installing a default tunnel route.
3. Apply NetworkExtension IPv4/IPv6 routes and DNS settings.
4. Duplicate the utun descriptor and start the userspace stack with the live NP/2 multiplexer.
5. Report the tunnel started only when all four stages succeed.

Shutdown closes the IP stack, duplicated descriptor, active NP/2 streams, multiplexer, and carrier exactly once. A data-plane exit after successful startup cancels the system tunnel with a sanitized error.

## Verification Gates

- Unit tests cover key separation, nonce construction, round-trip encryption, tampering, replay, reflection, ordering, truncation, and counter exhaustion.
- Authenticated session tests prove carrier payloads after confirm do not contain plaintext target metadata or stream payload.
- TUN dialer tests prove numeric IPv4 and IPv6 destinations become canonical NP/2 targets and UDP is rejected without a network side effect.
- Darwin utun adapter tests prove that the 4-byte address-family prefix is validated and restored for IPv4 and IPv6, including an exact-MTU packet.
- `go test ./...`, race-focused session tests, `go vet ./...`, Swift unit tests, and an iOS device build pass.
- A physical-device request through the system VPN returns the NP/2 server exit address with no loopback SOCKS listener in the Packet Tunnel process.
- On the physical iPhone and the same cellular path, the optimized HTTPS carrier reaches at least twice the recorded 8.69 Mbit/s peak while the `web` cover profile and 30% overhead cap remain configured.
- Production server and client are upgraded together because cell AEAD is mandatory.

## Pinned Dependency

The iOS userspace TCP/IP adapter uses `github.com/xjasonlyu/tun2socks/v2` v2.6.0, pinned by module checksum. Its public `proxy.Dialer` and FD-based endpoint are used directly; its SOCKS implementation and command engine are not used. The dependency is MIT licensed and uses a gVisor userspace network stack.
